# 云效（Yunxiao）平台分析与适配器设计参考

## 文档信息

| 字段 | 值 |
|------|-----|
| 用途 | Issuer 云效适配器开发参考 |
| 适配器优先级 | P1（阶段二交付） |
| 平台全称 | 阿里云·云效（Apsara DevOps） |
| 核心模块 | Projex（项目协作）、Testhub（测试管理） |

---

## 1. 平台概述

云效是阿里云提供的一站式研发协作平台，覆盖需求管理、项目协作、代码管理、CI/CD、测试管理等全流程。Issuer 需要对接的核心模块：

- **Projex**：项目协作，管理需求、任务、缺陷、迭代、路线图。
- **Testhub**：测试管理，管理测试用例、测试计划、测试报告。

---

## 2. 云效工作项体系

### 2.1 工作项层级结构

```
主题（Theme）
  └── 业务需求（Business Requirement）
        └── 产品需求（Product Requirement）
              ├── 任务（Task）
              │     └── 子任务（Sub-task）
              └── 缺陷（Bug/Defect）
```

### 2.2 工作项类型详解

| 云效类型 | 说明 | Issuer 映射 |
|----------|------|-------------|
| 主题（Theme） | 聚合散点需求，评估价值/成本，优先级排序 | Epic |
| 业务需求 | 面向业务目标的高层需求 | Epic / Story（视粒度） |
| 产品需求 | 面向产品的可交付需求 | Story |
| 任务 | 具体的开发/设计工作 | Task |
| 子任务 | 任务的进一步分解 | Sub-task（Task 的子项） |
| 缺陷 | 软件行为偏差 | Bug |

### 2.3 与 Issuer 统一模型的映射

| Issuer 类型 | 云效映射（推荐） | 备选映射 |
|-------------|-----------------|---------|
| **Epic** | 主题 或 业务需求 | 取决于项目配置 |
| **Story** | 产品需求 | 业务需求（如无产品需求层级） |
| **Task** | 任务 | 子任务 |
| **Bug** | 缺陷 | — |

> **注意**：云效的需求层级比 Issuer 更丰富（主题→业务需求→产品需求），适配器需支持用户配置映射关系。

## 3. 工作项字段体系

### 3.1 通用核心字段

| 字段 | 类型 | 必填 | Issuer 对应字段 |
|------|------|------|-----------------|
| 标题 | string | 是 | title |
| 描述/内容 | rich text | 否 | description |
| 负责人 | user | 否 | assignee |
| 参与者 | user[] | 否 | — (扩展字段) |
| 抄送人 | user[] | 否 | — |
| 优先级 | enum | 否 | priority |
| 截止时间 | datetime | 否 | due_date (扩展) |
| 状态 | enum (状态流) | 是 | status |
| 标签 | string[] | 否 | labels |
| 所属迭代 | reference | 否 | — (扩展字段) |
| 父工作项 | reference | 否 | parent_id |

### 3.2 优先级映射

| Issuer 优先级 | 云效优先级 | 说明 |
|---------------|-----------|------|
| critical | P0 | 紧急/阻塞 |
| high | P1 | 高优先级 |
| medium | P2 | 中优先级 |
| low | P3 | 低优先级 |

### 3.3 自定义字段

云效支持项目级自定义字段，适配器需要：
- 通过 `get_metadata()` 获取项目的字段定义。
- 在 `field_mappings` 配置中支持自定义字段映射。
- 工作项模板可自定义字段的新增、删除、排序、必填设置。

## 4. 状态流转

### 4.1 典型需求状态流

```
待规划 → 开发中 → 测试中 → 待验收 → 已完成
                                        ↓
                                      已关闭
```

### 4.2 典型缺陷状态流

```
待确认 → 修复中 → 待验证 → 已关闭
   ↓                        ↑
 已拒绝 ─────────────────────┘
```

### 4.3 状态自动化规则

云效支持自动化规则驱动状态流转：
- 子任务全部完成 → 父需求自动流转到"待验收"
- 代码合并 → 关联需求自动流转到"测试中"

适配器在 `update_item` 时需注意：
- 某些状态流转可能被自动化规则覆盖。
- 非法的状态跳转会被平台拒绝（需先通过 `get_metadata()` 获取合法流转路径）。

## 5. 关联能力（研发资产）

### 5.1 支持的关联类型

| 关联类型 | 说明 | Issuer `link_to_code` 适用 |
|----------|------|---------------------------|
| 代码提交（Commit） | 关联 git commit | 是 |
| 合并请求（MR） | 关联 Merge Request | 是 |
| 代码分支（Branch） | 关联开发分支 | 是 |
| 设计文件 | UI/UX 设计稿 | 否 |
| 产品文档 | 钉钉文档等 | 否 |
| 测试用例 | 关联 Testhub 用例 | 否（通过测试模块） |
| 缺陷 | 需求关联缺陷 | 否（内部关联） |

### 5.2 代码关联实现

云效的代码关联通过"研发资产"功能实现：
- 工作项可关联同一云效组织下的代码仓库的 Commit、MR、Branch。
- 适配器的 `link_code()` 需要调用云效 API 将代码引用附加到工作项。

## 6. 视图与查询能力

### 6.1 支持的视图模式

| 视图 | 说明 | `query_items` 适用 |
|------|------|-------------------|
| 列表视图 | 扁平列表，支持批量操作 | 是（默认） |
| 树形视图 | 展示父子层级关系 | 是（需包含层级信息） |
| 看板视图 | 按状态列展示 | 部分（按状态分组查询） |
| 甘特视图 | 时间轴展示 | 否（前端展示用） |

### 6.2 筛选与排序

适配器的 `query_items` 需支持的筛选维度：
- 状态（单选/多选）
- 优先级
- 负责人/参与者
- 工作项类型
- 所属迭代
- 截止时间范围
- 标签
- 自定义字段

排序支持：
- 截止时间
- 优先级
- 创建时间
- 更新时间

## 7. 迭代管理（Sprint）

### 7.1 迭代概念

云效的迭代等同于 Scrum Sprint：
- 固定时间窗口（一般 1-4 周）
- 包含一组计划完成的工作项
- 支持迭代锁定（防止范围蔓延）
- 提供燃尽图跟踪进度

### 7.2 适配器需支持的迭代操作

| 操作 | 说明 |
|------|------|
| 列出迭代 | 获取项目下所有迭代 |
| 将工作项加入迭代 | 创建/更新时指定迭代 |
| 按迭代筛选工作项 | `query_items` 支持迭代过滤 |

## 8. 路线图与里程碑

### 8.1 路线图

- 可视化甘特图规划需求交付时间线。
- 支持按需求类型选择规划对象（业务需求/产品需求）。
- 需求可在路线图中直接拆解子项。
- 颜色标识：蓝色（正常）、红色（延期）、灰色（已完成）。

### 8.2 里程碑

- 标记项目重要节点（发布日期、阶段性目标等）。
- 核心属性：负责人、预计完成时间、实际完成时间。
- 配合风险管理使用。

### 8.3 适配器映射

Issuer 暂无路线图/里程碑的统一抽象，可作为扩展字段处理：
- 创建 Story 时可选指定里程碑关联。
- 路线图信息作为只读元数据返回。

## 9. 测试管理（Testhub）

### 9.1 核心流程

```
设计测试用例 → 规划测试计划 → 执行测试 → 生成测试报告
```

### 9.2 测试用例结构

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 标题 | string | 是 | 用例名称 |
| 前置条件 | text | 否 | 执行前需满足的条件 |
| 操作步骤 | text/table | 否 | 文本模式或表格模式（步骤+预期结果） |
| 预期结果 | text | 否 | 期望的输出/行为 |
| 优先级 | P0/P1/P2/P3 | 否 | 默认 P3 |
| 类型 | enum | 否 | 功能测试、性能测试等 |
| 负责人 | user | 否 | 用例设计负责人 |
| 标签 | string[] | 否 | 分类标签 |
| 附件 | file[] | 否 | 相关文件 |

### 9.3 用例库管理

- **组织方式**：按产品/模块建立独立用例库。
- **目录结构**：树形目录（产品/子产品/模块/功能/场景），最多8层。
- **公开性**：公开库（组织全员可见）/ 私密库（仅成员可见）。
- **编号规则**：4位字母库编号 + 数字序号（如 `PROJ0001`）。
- **跨项目复用**：用例库中的用例可被多个项目的测试计划引用。

### 9.4 导入/导出能力

| 格式 | 导入 | 导出 | 说明 |
|------|------|------|------|
| Excel | 是 | 是 | 需使用官方模板；目录用 `\|` 分隔 |
| Xmind | 是 | 否 | 使用节点标注（tc、pc、tx 等） |
| PDF/图片 | 否 | 是 | 测试报告导出 |

### 9.5 测试计划

| 属性 | 说明 |
|------|------|
| 计划名称 | 自定义 |
| 开始/结束日期 | 时间范围 |
| 管理员 | 进度和质量负责人 |
| 参与人 | 测试执行人员 |
| 关联项目 | 可选，绑定到具体项目 |
| 关联迭代 | 可选，跟随开发迭代节奏 |
| 公开性 | 公开/私有 |

### 9.6 测试执行状态

```
未执行 → 通过 / 失败 / 阻塞 / 跳过
```

执行过程中可：
- 添加执行记录（截图、日志等）
- 直接创建缺陷并关联

### 9.7 Issuer 测试用例生成与云效对接

Issuer 的"测试用例生成"功能（Gherkin 格式）可通过以下方式对接云效：

1. **直接创建**：通过 API 在指定用例库中创建用例。
2. **Excel 导入**：生成符合云效模板格式的 Excel，用户手动导入。
3. **映射转换**：

| Issuer Gherkin | 云效用例字段 |
|----------------|-------------|
| Feature 标题 | 用例目录名 |
| Scenario 标题 | 用例标题 |
| Given... | 前置条件 |
| When... | 操作步骤 |
| Then... | 预期结果 |

## 10. 云效特有概念（Issuer 需关注）

### 10.1 原始诉求管理

云效支持"原始诉求"作为需求前的原始输入：
- 来自客户、市场、内部反馈的未经处理的需求描述。
- 可转化为正式的产品需求。
- **Issuer 关联**：Agent 传入的 `raw_text` 可映射为原始诉求，经 AI 增强后转为产品需求。

### 10.2 主题化管理

- 聚合散点需求，形成业务主题。
- 支持价值评估和成本评估。
- 根据评估分数排序优先级。
- **Issuer 关联**：可作为 Epic 的增强实现。

### 10.3 度量统计

云效内置的统计报表：
- 需求交付统计（趋势、累积流图、交付速率）
- 缺陷交付统计（趋势、存量占比、修复速率）
- **Issuer 关联**：`get_sync_status` 可附带基础统计信息。

### 10.4 自动化规则

云效支持条件触发的自动化操作：
- 状态自动流转
- 字段自动填充
- 通知自动发送
- **适配器注意**：push 工作项时可能触发平台侧自动化规则，导致状态与预期不一致，需在 pull 时重新同步。

## 11. 适配器接口设计要点

### 11.1 初始化（initialize）

适配器启动时需获取：
- 组织 ID 和项目 ID
- API 认证 Token
- 当前项目的工作项类型列表
- 当前项目的字段定义
- 当前项目的状态流转图
- 可用迭代列表

### 11.2 类型映射配置

```yaml
# 云效适配器类型映射示例
yunxiao_type_mappings:
  epic: theme          # 或 business_requirement
  story: product_requirement
  task: task
  bug: defect
```

用户可在 `issuer init` 向导中选择映射方式（因为不同项目模板的类型可能不同）。

### 11.3 API 调用注意事项

| 注意事项 | 说明 |
|----------|------|
| 认证方式 | OAuth 2.0 或 Personal Access Token |
| API 限流 | 需处理 429 状态码，实现限流退避 |
| 分页查询 | 使用 cursor-based 或 offset-based 分页 |
| 字段校验 | 必填字段缺失时 API 会返回 400，需预校验 |
| 状态流转校验 | 非法状态跳转会被拒绝，需先查询合法路径 |
| 富文本格式 | 描述字段支持 Markdown/HTML，需确认 API 接受格式 |

### 11.4 错误处理

| 错误码 | 含义 | 适配器行为 |
|--------|------|-----------|
| 401 | Token 过期/无效 | 返回认证错误，提示用户更新凭证 |
| 403 | 权限不足 | 返回权限错误，提示所需权限 |
| 404 | 工作项/项目不存在 | 返回不存在错误 |
| 429 | 限流 | 自动退避重试 |
| 500 | 服务端错误 | 记录日志，自动重试 |

## 12. 与其他适配器的差异对比

| 维度 | GitHub | GitLab | 云效 | Jira |
|------|--------|--------|------|------|
| 工作项层级 | 扁平（Issue + Label） | Issue + Epic | 多层（主题→业务需求→产品需求→任务） | Epic → Story → Task |
| 优先级表达 | Label | Label/Weight | P0-P3 内置字段 | Priority 字段 |
| 迭代概念 | Milestone | Milestone/Iteration | 迭代（Sprint） | Sprint |
| 测试管理 | 无内置 | 无内置 | Testhub 内置 | 需插件（Zephyr 等） |
| 代码关联 | 自动（commit message） | 自动（commit/MR） | 研发资产关联 | Development Panel |
| 自动化规则 | GitHub Actions | GitLab CI + Rules | 内置自动化引擎 | Automation Rules |
| 自定义字段 | 无 | 无（仅 Label） | 支持 | 完善支持 |

## 13. 开发计划

### 阶段二交付范围

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 基础 CRUD | 高 | 创建/查询/更新/删除工作项 |
| 类型映射 | 高 | 支持用户配置 Issuer 类型到云效类型的映射 |
| 状态流转 | 高 | 查询合法路径，执行状态更新 |
| 代码关联 | 高 | 将 PR/Commit/Branch 关联到工作项 |
| 迭代筛选 | 中 | 按迭代过滤工作项 |
| 优先级映射 | 中 | P0-P3 ↔ critical/high/medium/low |
| 双向同步 | 中 | 拉取平台变更，内容哈希比对 |
| 测试用例创建 | 低 | Issuer 生成的 Gherkin 用例推送到 Testhub |
| 路线图/里程碑 | 低 | 只读获取，作为元数据返回 |
